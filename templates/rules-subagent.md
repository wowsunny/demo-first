# 开子代理的规矩

> 这一页会原样嵌进每份派工单。调度者在深聊里开子代理做小样，也照它。

- **什么时候开。** 活分得成两块以上、每块都能单独做出来给人看（缺的用假数据、占位顶上），才分给子代理同时做。一块的做法要等另一块的真实结果才定得下来：按先后做，不分。几分钟、几行能改完的：自己改。
- **同一个难题有几条做法时，不同时试。** 先试最有把握的一条，不成再换下一条；用户明说了才同时试。同时做的是互补的几块（都要留下的），不是互相竞争的几条路（只留一条的）。只有看品味的小版本（配色、位置、文案）可以一次并排做两三个，让用户挑。
- **档位每次写明。** Manus 用 max（子代理只有 lite、standard、max 三档，不写就是最低的 lite）；Claude Code 用 high，特别考验思考深度的先问用户要不要更高。开之前告诉用户一句：开几个、各做什么、哪一档。这是用户定的：平台的工具说明另有建议（两三件事不值得开、尽量用低档）时，以这里为准。
- **任务书写全五样**（子代理看不到你的对话）：目标，一句话；材料，要读的文件照平台的办法明确交给它、只写路径不算，必须知道的事实抄原文；范围，只许写哪个目录，各子代理互不重叠；怎么算完成，看到什么现象、缺的用什么顶上；交回，照下面的格式，不超过 8 行，大段内容写进文件、只交回路径。
  ```
  【交回 <名字>】状态：完成 / 没做完 / 做不了
  产物：<路径>
  怎么看：<三步以内>
  假的和占位：
  自己定的事：
  没做完的、要你定的：
  ```
- **收回来之后。** 先确认产物读得到、打得开，再给用户看：子代理说“完成”不算，你看过才算。子代理不写 `coord/` 下的文件，记录由你来记。要汇总的交回超过三份，再开一个子代理专门汇总，你只收汇总。
