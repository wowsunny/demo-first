## 0. 用户的话

> /demo-first 做一个网页工具：对着手机说一段话，它自动整理成待办清单。要一个线上链接，代码也要。

做什么、交什么都有了，直接建台账。用户没提期限，就不问：节奏由他掌握。

## 1. 深聊

```bash
python3 $SKILL/scripts/init_ledger.py --name 语音待办 --goal "说一段话，自动整理成待办清单的网页工具"
```

脚本建好 `coord/`，并说明会话上限：同时 3 个探索者，1 个建设者，1 个监管者。

**第一轮问**（每轮最多 3 个问题，每个带推荐）：

```
先问三件最影响怎么分工的事，不回就按推荐走：
1. 清单要不要能分享给别人看？推荐：要，只读链接。这决定清单存在浏览器里还是服务器上。
2. 一段话里有两件事，要拆成两条待办吗？推荐：要拆，这是这个工具和普通语音输入的差别。
3. 主要在手机上用还是电脑上用？推荐：手机，按住说话。
```

用户回：“都按推荐。按钮我想要大一点，单手够得着，具体多大你给我看看。”

**当场归类。** 这一轮冒出四个没把握的点：

| 没把握的点 | 归哪一类 | 为什么 |
|---|---|---|
| 说话按钮多大、放哪 | 小样 | 一句话说得清，子代理几分钟做得出，用户看一眼就能定 |
| 手机浏览器里把中文语音转成文字，3 秒内出字 | 待探索 | 有几条技术路线，要在用户自己的手机上来回试 |
| 从一段口语里拆出一条条待办和时间 | 待探索 | 要拿一批样例句子来回调，对几成才算行，得和用户商量 |
| 松手之后、出结果之前，页面上给什么反馈 | 待探索 | 看感觉，要改好几轮 |

**小样。** 调度者开两个子代理（档位 max），一个把按钮放底部正中、一个放右下角，各写一个单文件网页到 `lab/quick/`，同时接着问用户下一轮问题。两份交回来是这样的：

```
【交回 按钮-底部正中】状态：完成
产物：lab/quick/button-center.html
怎么看：手机上打开，单手握持，用拇指按住中间的圆钮
假的和占位：按住只变色，不录音
自己定的事：圆钮直径 88 像素 — 比拇指肚略大 — 错了改一个数
没做完的、要你定的：无
```

调度者先确认两个文件都打得开，再发给用户看。用户说：“底部正中这个好，就它。”调度者记进 `coord/CHARTER.md` 的“已经定了的事”和 `coord/BOARD.md` 的“小样”。这个点不用再开会话。

**验收项**（写进 `coord/CHARTER.md`）。每条都是“用户做什么 → 看到什么”：

1. 按住按钮说“明天下午三点交周报，顺便订周五的会议室” → 松手后 5 秒内，清单里多出两条待办，其中一条带“明天 15:00”
2. 点一条待办的文字 → 能改内容和时间，改完立刻保存
3. 勾掉一条待办 → 它移到“已完成”，刷新页面还在
4. 点“分享” → 得到一个只读链接，别人打开看得到清单、改不了
5. 在手机上打开首页 → 不用横向滚动，说话按钮单手够得着

不好的写法：“语音识别准确”“界面美观”。没法当场验证，监管者也没法逐条对。

## 2. 定分工

**三个待探索的点，哪些要合。** 两两之间看四处：

| 这两个点 | 输入 | 输出 | 预期效果 | 交互 | 结论 |
|---|---|---|---|---|---|
| 语音转文字 和 拆待办 | 前一个的输出是后一个的输入，但中间只是“一段文字”，格式定得死 | 各出各的 | 可以各自验：转出来的字对不对；拿一段现成的文字拆得对不对 | 不互相等 | 分开。把“一段文字”写进接口约定 |
| 语音转文字 和 松手后的反馈 | 反馈要跟着识别的进度走，识别改成边说边出字，反馈就得重做 | 落在同一块界面上 | 用户说的“松手要马上有反应”，要两样放在一起才看得出 | 是同一段交互 | 合成一个会话 |

所以分成两个探索会话：E1“说话到出字”（语音转文字连同松手后的反馈），E2“口语拆待办”。清单的增改查、完成、存储、只读分享都说得准，全归建设者 B1。

`coord/BOARD.md` 的“接口约定”：

```
- E1 → B1：transcribe(录音) → { 文字, 用时毫秒 }。E1 出结果前，B1 用“固定返回一句话”的假实现顶着。
- E2 → B1：extract(文字) → [{ 事项, 时间 }]。E2 出结果前，B1 用“整段当成一条待办”的假实现顶着。
- E1 和 E2 之间只传一段文字，互不等。
```

**分工确认的后半段**（前半段是脚本填进去的初始设定）：

```
**二、分工**

你回“开”之后，我在这个项目里把下面每一行各开成一个独立的会话，行首就是它的名字：

- 语音待办 - 探索者 - 说话到出字（E1）｜手机浏览器里按住说一句中文，松手后 3 秒内出字，这期间的反馈让人觉得“马上有反应”
- 语音待办 - 探索者 - 口语拆待办（E2）｜从一段口语里拆出待办（事项和时间），10 句样例能对几句
- 语音待办 - 建设者（B1）｜架构和骨架；清单的增改查、完成、存储、只读分享；落地和交付
- 语音待办 - 监管者（S1）｜全局巡检和验收

**三、要你定的**（不回就按推荐走）

1. 语音识别可以调用收费的模型接口吗？推荐：可以。E1 先试免费的办法，不够好再用收费的。
```

用户回：“开。按推荐。”调度者把这件定下的事加进 `coord/CHARTER.md` 的“已经定了的事”，初始设定从此冻结。

## 3. 派工

顺序是探索者、建设者、监管者，每开一个就把链接记进 `coord/BOARD.md`。

```bash
python3 $SKILL/scripts/new_brief.py explorer E1 "说话到出字"
```

脚本的输出：

```
已生成 coord/briefs/E1.md（探索者）
开任务时照这三样指定，不用平台默认的：
  会话名：语音待办 - 探索者 - 说话到出字
  思考强度：超高（Manus 是 Max 的超高档 max-extra；Claude Code 是 xhigh）
  要附的：没有。
还要你填的 4 处：……
```

调度者只填四处。E1 的：

- **你要回答的问题：** 在手机浏览器里按住按钮说一句中文，松手后 3 秒内能不能拿到基本准确的文字，并且这 3 秒里的反馈让用户觉得“马上有反应”？
- **你需要知道的事实：**
  - 验收项 1（原文）：按住按钮说“明天下午三点交周报，顺便订周五的会议室” → 松手后 5 秒内，清单里多出两条待办，其中一条带“明天 15:00”。这 5 秒里，后面“把文字整理成待办”那一步还要占大约 2 秒，所以留给你的只有 3 秒。
  - 用户已定：可以调用收费的模型接口，但先试免费的办法，不够好再用收费的。
  - 用户已定（小样试过）：说话按钮放在底部正中，圆钮直径 88 像素。用户原话：“底部正中这个好，就它。”
- **和别的会话的接口：** 你的结果由建设者接进正式项目的 `transcribe(录音) → { 文字, 用时毫秒 }`。“文字 → 待办”归另一个探索者 E2，你不用做；要演示完整效果时，把文字原样显示出来就行。
- **怎么算完成：** 用户在自己的手机上打开你的 demo，按住说验收项 1 里那句话，松手后 3 秒内页面上出现文字，“明天下午三点”“周报”“周五”“会议室”这四处都没有错；松手的一瞬间页面上就有反馈。页面上同时显示这次用了多少秒。

注意四点：问题只有一个，是把分不开的两件事合成一句来问的；事实是原文抄进去的，还替它算好了“5 秒里它占 3 秒”；接口写明了归谁、不用做什么；完成的标准是用户能当场验证的现象。

建设者和监管者的派工单，脚本会从 `coord/BOARD.md` 里取出别的会话的名字和链接填进去。监管者的那一份没有要手填的地方。开建设者时把 E1、E2 的任务作为任务引用附上；开监管者时把其余任务和调度者自己的任务都附上。

各会话和调度者共用一个文件夹时（比如在 Manus 桌面应用里打开了 Work locally），派工单不用整份发：第一条消息只写会话名和派工单的路径，见 `manus-platform.md` 第三节。

## 4. 交棒

监管者开工后做了第一次巡检，它的最后一条消息第一行没有写“读不到别的任务”，说明它读得到。调度者给用户发一条短消息，然后退出主线：

```
会话都开好了，档位请在各会话的模式菜单里核对一下：
- 语音待办 - 探索者 - 说话到出字｜Max 超高｜https://manus.im/app/…E1
- 语音待办 - 探索者 - 口语拆待办｜Max 超高｜https://manus.im/app/…E2
- 语音待办 - 建设者｜Max 超高｜https://manus.im/app/…B1
- 语音待办 - 监管者｜Max 极致｜https://manus.im/app/…S1

先去“说话到出字”：它给出第一版 demo 后，用你的手机试着说一句。建设者会发来边界和架构的提案，有意见在那里回。
探索定稿后：去建设者那里说一句“E1 定稿了”。
想看全局、想知道下一步去哪：去监管者那里说“巡检”。
要改分工或初始设定：回我这里。
节奏由你掌握。想让会话换挡，在那个会话里说，或者回我这里说一句，我转给它们：“先到这里”“冻结”“交付”“总检查”。
```

## 5. 之后：用户在各个会话里推进

**探索者里。** E1 第一轮先开了两个子代理，同时试两条路：A 用浏览器自带的识别，B 录音后发给语音模型。开之前它告诉用户：“开两个子代理，各试一条路，都用 max 档。”用户在自己的手机上各试了几次，又来回调了两轮松手后的反馈，然后说“定了”。E1 的最后一条消息是：

```
【回报 E1】状态：完成
结论：成
做了什么：试了两条路。A 用浏览器自带的识别，B 录音后发给语音模型。A 在一部分手机上按住说话拿不到结果；B 在试过的两部手机上都稳，松手后 1.5～2.5 秒出字。
证据：demo https://…/e1-demo（页面上显示每次用时）。用户在自己的手机上试了 5 次，都在 3 秒内，四处关键词全对。
自己定的事：录音最长 60 秒，超过自动停 — 一段待办说不了这么久 — 错了的代价是长段话被截断
要谁决定：无
延后的事：没有网络时的提示；用户不给麦克风权限时的提示
下一步：无，等落地

移交说明 E1
1. 结论：成。走“录音后发给语音模型”这条路。
2. demo：https://…/e1-demo。打开，按住中间的按钮说话，松手，看下方的文字和用时。
3. 落地时必须保持的：按住才录、松手即发；松手的一瞬间按钮变成转圈并显示“正在识别”；用户原话：“松手以后要马上有反应，哪怕先给个转圈。”
4. 建议的接口：transcribe(录音) → { 文字, 用时毫秒 }；失败时返回错误原因。
5. 踩过的坑：路线 A 不要再试；两种手机浏览器各自支持的录音格式不一样，demo 里的 pickFormat() 已经处理。
6. 没解决的和延后的：没有网络、没有麦克风权限时的提示。
7. 验收对照：① 松手后 3 秒内出字 ② 验收项 1 那句话四处关键词都对 ③ 松手的一瞬间就有“正在识别”的反馈。
8. 相关文件：lab/E1/index.html、lab/E1/recorder.js（约 80 行，太长不贴）。

下一步请去“语音待办 - 建设者”说一句：E1 定稿了。
```

E2 那边调了三轮，“下周三”这类说法还是对不上。它照派工单停下来，给了自己的判断：降级方案，只认“今天、明天、星期几、几点”。用户说：“先到这里，就用降级的。”E2 照现状交了移交说明。

**建设者里。** 用户去 B1 说“E1 定稿了”。B1 先把移交说明和 `lab/E1/` 里的文件读完再动手：把 `src/voice/transcribe.ts` 的假实现换成真的，照移交说明第 7 节逐条比过，在回报里写明三条都对上了。它没有为这件事开子代理：只动一个目录，自己做更快。

稍后 E2 也定稿了。这时 B1 手里有三块互不相干的活：落地 E2、做分享链接的只读页、补编辑待办的表单。三块各自都能单独打开看，它先定好三块之间的接口，再开三个子代理同时做，每个只动自己的目录；路由和全局样式由它自己改。

**监管者里。** 用户去 S1 说“巡检”。S1 重读初始设定和 `coord/WATCH.md`，然后每个会话交给一个只读的子代理去看，再由一个子代理汇总。它的输出：

```
【巡检 S1 #2】16:35
看了什么：E1、E2、B1 的最后一条消息和文件；正式项目的预览链接，手机宽度下走了一遍验收项 1～3
各会话：
- 语音待办 - 探索者 - 说话到出字 — 完成 — 已落地
- 语音待办 - 探索者 - 口语拆待办 — 完成 — 降级：只认“今天、明天、星期几、几点”
- 语音待办 - 建设者 — 进行中 — 三个子代理在做 E2 落地、分享页、编辑表单
提醒：
1. B1 的分享页现在谁打开都能改清单，在 src/share/ — 和验收项 4“改不了”不符 — 建议去建设者那里说：分享页要只读
建议你下一步：
1. 去建设者：告诉它分享页要只读。
2. 去建设者：有一张“添加密钥”的卡片等你点。
延后清单新增：没有网络时的提示（来自 E1）；“下周三”这类说法（来自 E2）
```

**收尾和交付。** 用户觉得功能够了，回调度者那里说“冻结”。调度者把这句话转给建设者，并记进 `coord/DECISIONS.md`。建设者从这时起只修不加。修得差不多了，用户去 B1 说“交付”。B1 做最后一次发布，在线上链接上把五条验收项走了一遍，然后写：

```
【交付说明】说完就有待办
- 线上链接：https://…
- 代码：正式项目“voice-todo”，已同步到 GitHub：https://…
- 验收项：1 通（实测 4.1 秒） 2 通 3 通 4 通 5 通
- 各会话：B1 https://… ｜E1 https://… ｜E2 https://… ｜S1 https://…
- 探索的结论：E1 成，录音后发给语音模型；E2 降级，只认“今天、明天、星期几、几点”，“下周三”这类按下一个周三算
- 没做的：到点提醒（初始设定里就不做）；长于 60 秒的录音
- 已知问题：没有网络时只提示“识别失败”，没有说明原因；分享链接没有过期时间
```

用户再去 S1 说“总检查”。S1 在线上链接上把五条验收项亲自走了一遍，逐条标了“通”，并列出延后清单里还没处理的两条，由用户决定写进已知问题。
