SKILL.md 的流程是照 Manus 的说法写的。在 Claude Code 里，五步流程、台账、派工单、脚本都不变，只把“开任务、读回报、发消息、发布”这些动作换成本页的做法。开始立项之前，把这一页读完。

## 一、先看你能开哪一种任务

Claude Code 里有两种并行的任务。看你的工具列表里有哪一种；没看到的，先用工具搜索找一下再下结论。

| 你有的工具 | 探索者、总建设者、落地建设者 | 监管者 |
|---|---|---|
| 能开**子会话**的工具：开出来的是一个独立的会话，用户能点开它、直接在里面对话。Claude 桌面应用里是 `start_session` | 开成子会话。用户直接进探索者的会话聊，和 SKILL.md 写的一样 | 全新的后台子代理 |
| 只有开**子代理**的 Agent 工具（有的版本叫 Task） | 开成后台子代理。子代理不能和用户对话，用户的话由你转 | 全新的后台子代理 |

两种都有时用第一行。监管者总是用子代理：它只读、每次都要不带成见地从头看，结果也要整段交回给你。

下面凡是两种做法不一样的地方，都分开写了“子会话”和“子代理”。

## 二、动作对照

两种做法相同的：

| SKILL.md 里说的 | 在 Claude Code 里 |
|---|---|
| Project | 用户的项目目录，也就是你现在的工作目录。台账 `coord/` 建在这里。所有任务都在这一个目录里工作，互相看得到文件 |
| 给已有的任务发消息 | 用 SendMessage，发给开任务时工具返回的那个编号或名字，它带着原来的上下文接着做。工具列表里没看到 SendMessage，先用工具搜索找一下；确实没有：新开一个任务，把原派工单、它上一次的回报、这次要说的话都放进去 |
| 开任务时附上正式项目的网站（Edit in new task） | 不用附。正式项目就在同一个目录里，派工单的“范围”里写清路径 |
| 把任务作为任务引用附给另一个任务 | 不用附。把要读的文件的路径写进派工单：探索者的 demo 在 `lab/<编号>/`，移交说明在 `coord/handoffs/<编号>.md` |
| 把 `coord/PROJECT_INSTRUCTION.md` 写进 Project 的主指令 | 跳过。派工单是自含的。不要去改用户的 `CLAUDE.md` |
| 某个任务自己又开了子任务 | 允许。照 SKILL.md 的规矩，要它把新任务的编号写进回报 |
| 发布正式站 | 见第八节 |

两种做法不同的：

| SKILL.md 里说的 | 子会话 | 子代理 |
|---|---|---|
| 开一个独立任务，把派工单全文作为它的第一条消息 | 用开子会话的工具开一个新会话。标题写“编号 + 标题”；任务内容是第三节的那几行；不带你现在的对话；和你共用这个文件夹，不要让它另开 worktree；思考强度明确设成 high，不要让它继承你的，否则同样的活会重十几倍。用户回的“开”就是用户要你开这些会话，工具问是谁要开的，照实选用户要求的 | 用 Agent 工具开一个**后台**子代理。prompt 是第三节的那几行。要同时跑的几个，在同一条消息里一起开 |
| 任务链接 | 工具返回的会话编号。记进 `coord/BOARD.md`；跟用户提到这个会话时，写成他能点开的链接 | 工具返回的子代理名字或编号。记进 `coord/BOARD.md` |
| 查任务的状态，读它最后一条消息里的【回报】 | 它每结束一轮，会有一条通知到你这里，只带开头的几百个字。完整的【回报】去读 `coord/tasks/<编号>.md` 的“最近一次回报”一节 | 不用去查。它每做完一轮，最后一条消息会自动交回给你，那就是它的【回报】。还没交回的就是还在跑 |
| 用户直接进探索者的任务聊 | 能，见第五节 | 不能，由你传话，见第五节 |
| 任务在等用户点确认，不要给它发消息 | 确认的提示出现在那个会话里，要用户进去点。写进阶段报告，请用户去点 | 这一条不适用。确认的提示直接出现在主会话里，上面写着是哪个子代理要的 |

文件共用带来两处简化：

- **移交说明不用你来存。** 探索者照【平台说明】把它存成 `coord/handoffs/<编号>.md`，这个文件就在共用的台账里。你只确认它在、八节齐全。
- **各任务的记录你都读得到。** `coord/tasks/<编号>.md`、总建设者的 `coord/ARCHITECTURE.md`、监管者的 `coord/WATCH.md`。仍然守“一个文件只有一个写者”：别人的文件你只读不改。

探索者的 demo 一律放在 `lab/<编号>/`，和正式项目的代码分开。正式项目的代码只有建设者动。

## 三、开任务时加在派工单前面的几行

派工单已经在共用的目录里，不用把全文再贴一遍：开任务时只发下面这几行，里面给出派工单的路径。照抄，把尖括号里的换掉；倒数第二行按角色选一句。

子会话用这一段：

```text
【平台说明】你是 Claude Code 里的一个独立会话，由调度者（主会话）为这个项目开出来。先读完这几行，再去读你的派工单。
- 工作目录：<项目目录的绝对路径>。派工单里说的“你的工作区”“代码库”都是它，台账在它的 coord/ 下。别的任务也在这个目录里工作。
- 用户会直接点进这个会话和你对话。
- 调度者只读文件，读不到这里的对话。所以派工单里“回报不用抄进文件”那一句在这里不适用：每一轮结束前，把【回报】整段写进 coord/tasks/<编号>.md 末尾的“最近一次回报”一节，替换掉旧的；最后一条消息的第一行写【回报 <编号>】和状态、结论。
- 派工单里说“预览链接”的地方：给本地文件的绝对路径。不要留下一直运行的进程；确实要起本地服务，在回报里写明地址和怎么停。
- <按角色选一句>
- 你的派工单：<项目目录的绝对路径>/coord/briefs/<编号>.md。现在把它完整读一遍，照它做。
```

子代理用这一段：

```text
【平台说明】你是 Claude Code 里的一个后台子代理。先读完这几行，再去读你的派工单。
- 工作目录：<项目目录的绝对路径>。派工单里说的“你的工作区”“代码库”都是它，台账在它的 coord/ 下。
- 你不能直接和用户对话。派工单里说“发给用户”“问用户”“等用户”的地方：把要说的话写在这一轮的最后一条消息里，然后结束这一轮。调度者会转给用户，再把用户的原话发回给你。以“用户说：”开头的就是用户的原话，和用户亲口对你说的一样对待。
- 派工单里说“预览链接”的地方：给本地文件的绝对路径。不要留下一直运行的进程；确实要起本地服务，在最后一条消息里写明地址和怎么停。
- <按角色选一句>
- 你的派工单：<项目目录的绝对路径>/coord/briefs/<编号>.md。现在把它完整读一遍，照它做。
```

| 角色 | 按角色选的那一句 |
|---|---|
| 探索者 | 你的 demo 只放在 `lab/<编号>/` 里，别的目录只读。定稿时，把移交说明也存一份到 `coord/handoffs/<编号>.md`。 |
| 总建设者 | 正式项目建在工作目录里（`lab/` 和 `coord/` 以外）。发布指的是部署到线上；部署、git 提交和推送，都先在回报的“要谁决定”里问用户。 |
| 落地建设者 | 只动派工单“范围”里写的路径。探索者的 demo 在 `lab/<探索者编号>/`，只读。不提交，不部署。 |
| 监管者 | 整个工作目录你都可以读，只许写 `coord/WATCH.md`。 |

## 四、派工这一步的顺序

SKILL.md 第 2 步在这里是这样走的，四件事都要做：

1. 逐份生成、填、查派工单：总建设者、每个探索者、监管者。监管者的也在这一步生成。
2. 把总建设者和探索者开出来。开成子代理时，在同一条消息里一起开。
3. 紧接着开监管者，做第 1 次巡检（见第六节）。这一次它查的是分工：每条验收项有没有任务管，任务之间有没有重叠或空档。
4. 给用户发一句话：开了哪些任务。子会话：告诉他先去哪个探索者的会话，给出链接。子代理：告诉他探索者拿出 demo 时你会叫他。这里不出阶段报告；第一份阶段报告，等有任务回报“完成”，或者用户说“报告”时再出。然后结束这一轮。

`clock.py --card` 每运行一次就占一个报告序号。只在真要出阶段报告时才运行它；平时看时间，用不带 `--card` 的 `clock.py`。

## 五、用户和探索者怎么聊

**子会话：用户直接进去聊。** 你做三件事：

1. 派完工，告诉用户先去哪个探索者的会话。两个探索者都在等他时，先去时间盒更早到的那个。
2. 收到某个会话结束一轮的通知：读它的 `coord/tasks/<编号>.md`，照 SKILL.md 第 3 步的表处理。它在等用户，而用户还没去：在你这里提醒一句，给出链接。
3. 用户在你这里对某个任务提了意见：用 SendMessage 把原话转过去，前面加“用户说：”。

**子代理：由你传话。** 探索者每一轮结束会交回一条消息：demo 在哪、请用户看什么、【回报】。

1. 它在等用户看 demo 或拿主意：马上告诉用户，不等阶段报告。只说三件事：demo 的路径或地址；它请用户看什么、它推荐哪个；“直接在这里回我，我原话转给它”。
2. 用户回了话：用 SendMessage 把**原话**发给那个探索者，前面加“用户说：”，不改写。你自己要补充的话另起一段，前面写“调度者：”，不要混进用户的话里。
3. 两个探索者同时在等用户：一次只带用户看一个，先看时间盒更早到的。另一个记在 `coord/BOARD.md` 里，等这个聊完再提。
4. 它的【回报】是“完成”：照 SKILL.md 第 3 步的表处理。

总建设者的架构提案、第一次部署前的询问，也这样转给用户。

阶段报告里“要你做的”：子会话照常写“去 E1：……”，附上会话的链接；子代理写“去 E1：……”，后面加一句“在这里回我”。不属于哪个任务的事（比如请用户自己打开页面走一遍），写“在这里：……”。

## 六、监管者每次都新开

监管者的用处是不带成见。所以每次巡检都**新开**一个后台子代理，不要用 SendMessage 续上一次的；它上次记下的事都在 `coord/WATCH.md` 里。

- 监管者的派工单 `coord/briefs/S1.md` 只生成一次，每次巡检都用它。
- “你怎么看到它们”一节，两句都不用，填这一句：`各任务的文件都在这个工作目录里，直接去读：coord/BOARD.md 是任务树，coord/DECISIONS.md 是跨任务的决定，coord/briefs/ 是各任务的派工单，coord/tasks/ 是各任务自己的记录，coord/handoffs/ 是移交说明；探索者的 demo 在 lab/，其余是正式项目的代码。各任务的对话你读不到；调度者每次请你巡检时，会把各任务最新一次回报的原文附在后面。`
- 每次的 prompt：第三节子代理的那一段，再加一段：

```text
【巡检请求】这是第 <N> 次巡检。现在 <钟点>，阶段：<阶段>。
这一轮新开的任务：<编号、角色，没有就写“无”>
这次请特别看：<一两件事，没有就写“无”>
各任务最新一次的【回报】原文：
<逐个贴上，只贴【回报】那一段，不改写；还没有回报的写“还没有回报”>
```

第 1 次巡检在派完工之后马上开。之后每出一份阶段报告开一次，不等它；它交回的【巡检】进下一份阶段报告。你刚给哪个任务发过消息、它还没回报，就等它回报了再开监管者：不然监管者读到的是改到一半的文件。

## 七、开工确认和派工单里要改的地方

- **开工确认** `coord/KICKOFF.md`：删掉开头那一整行 `{{当前任务不在 Project 里……}}`，和它下面“〇、请先建一个 Project”那一段。“四、接下来”的三行，子会话换成：

```text
- 回一个“开”，我就给上面每一行各开一个会话。它们会出现在侧栏里，都在这个项目目录里工作。
- 它们同时运行，用量比在一个对话里做到底要多。
- 开好之后，我告诉你先去哪个会话。探索者的会话你可以直接点进去聊。
```

  子代理换成：

```text
- 回一个“开”，我就把这些任务作为后台子代理开出来，它们都在这个项目目录里工作。
- 它们同时运行，用量比在一个对话里做到底要多。
- 探索者拿出 demo 时我会叫你来看。你对哪个任务有话说，直接在这里告诉我，我原话转过去。
```

- **交付物里有线上链接**：Claude Code 自己不带发布。在“三、要你定的”里问一句部署到哪，并给出你的推荐；用户没有现成的地方，就推荐先交能在本机打开的版本。
- **派工单里“上级：调度者任务（……）”**：填“主会话”。

## 八、发布和提交

- 只有总建设者部署。第一次部署前要问用户，这一条派工单里已经写了。
- git 提交和推送只在用户要求时做。交付时在阶段报告里问一次：要不要提交，提交到哪个分支。
- 所有任务共用一个文件夹，所以不要让两个任务同时改同一批文件。两个建设者的区域分不开时，照 SKILL.md 第 4 步的第 2 点交给总建设者。

## 九、走不通时

| 你遇到的情况 | 怎么办 |
|---|---|
| 开子会话的工具不肯直接开，要用户先点一下 | 照它说的做，等用户点。用户不想要这么多会话，就改用后台子代理 |
| 子会话结束了一轮，`coord/tasks/<编号>.md` 里没有新的【回报】 | 用 SendMessage 请它照【平台说明】把【回报】写进去 |
| 发给子会话的消息没被收下（对方要用户先批准，或者拒收） | 请用户进那个会话批准；批不了，就请用户把这句话直接带过去 |
| 子代理交回的消息里没有【回报】 | 用 SendMessage 请它照派工单“回报”一节的格式补发 |
| 开成了子代理，用户却想直接和某个探索者聊 | 请用户另开一个 Claude Code 会话，进同一个项目目录，把 `coord/briefs/<编号>.md` 全文贴进去。在 `coord/BOARD.md` 里注明这个任务由用户自己带，它的进展看 `coord/tasks/<编号>.md` |
| 子会话和子代理都开不了 | 退成单任务：照 `references/manus-platform.md` 第一节末尾的“退成单任务”做，其中“请用户新开一个任务做冷启动检查”换成“请用户另开一个 Claude Code 会话，把监管者的派工单贴进去” |
| 子代理不能在后台运行，开了就得等它做完 | 一次只开一个：先总建设者搭骨架，再逐个开探索者，最后开监管者。阶段报告里写明现在是排队执行 |
| 任务的回报里说它起了本地服务 | 把地址记进 `coord/BOARD.md`。用不着了就发消息请它停掉；它停不掉，就写进阶段报告告诉用户 |
| 用 `new_brief.py` 生成了派工单，又决定不开这个任务 | 运行 `clock.py --done <编号>`，把它占的并行名额还回去，并在 `coord/BOARD.md` 里写明没开 |
| 用户的项目目录里已经有代码 | 正式项目就是它。总建设者的派工单“你要交付的”里写明：先读懂现有的结构，`coord/ARCHITECTURE.md` 记现状和要加的部分 |
