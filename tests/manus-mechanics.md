# 在 Manus 上实测

两件事要在真实账号上测：技能本身好不好用（第〇组），和它依赖的平台行为是不是真的那样（第一到三组）。

- 需要：一个能同时跑多个任务的账号。Free 账号同时只能跑 1 个任务，只能测到“开不出并行任务”的退路。
- 用时：第〇组 20～30 分钟，第一组约 25 分钟，第二组约 10 分钟。
- 花费：会用掉一些积分。每一步的活都故意做得很小。
- 结果记在每组后面的表里。测完把表发回来，据此改 SKILL.md 的默认做法。

## 第〇组：试用技能本身

先做这一组。它直接回答“这个技能在 Manus 上跑不跑得起来”。

### 准备

1. 在仓库根目录运行 `python dev/pack.py`，得到 `dist/demo-first.zip`。
2. Manus → Skills → **+ Add** → **Upload a skill**，上传这个 zip。
3. 新建一个 Project，名字随意。把 demo-first 加进这个 Project 的技能库。
4. 在 Project 里新开一个任务，发下面这段话。

```text
/demo-first
我想做：一个网页版的番茄钟。25 分钟倒计时，结束时有提示音，并显示一句鼓励的话。
什么时候交：从现在起 2 小时，北京时间（+08:00）
交什么：线上链接
没把握的地方：结束时的提示音用哪一种好听又不吓人；鼓励的话是写死一组，还是让模型现写
```

### 边看边记

它开完任务会发一条短消息，告诉你先去哪个任务。你回一句“报告”，看到第一份阶段报告就可以停，后面的落地和交付留到完整冲刺时再看。想省积分，开出任务后可以把不看的任务停掉。

| 编号 | 看什么 | 结果 | 备注 |
|---|---|---|---|
| K1 | 它有没有运行 `init_ledger.py`；脚本跑没跑通（看它的操作记录里的输出） | | 技能目录的路径是： |
| K2 | 它有没有先写 `coord/CHARTER.md` 和 `coord/BOARD.md`，再用 `new_brief.py kickoff` 生成开工确认 | | |
| K3 | 开工确认是不是四段：初始设定、任务树、要你定的、接下来；发完有没有停下来等你 | | |
| K4 | 任务树拆得对不对：两个没把握的地方各是一个探索者，其余归总建设者，最后有监管者 | | |
| K5 | 你回“开”之后：有没有弹 **Allow these actions?**；它是不是逐份 `new_brief.py` → 填 → `check_brief.py` → 开任务 | | 开了几个任务： |
| K6 | 它有没有自己下场写番茄钟的代码 | | |
| K7 | 打开一个探索者任务：第一条消息是不是完整的派工单；它有没有照做（最小 demo、给预览链接、最后一条消息是【回报】） | | |
| K8 | 打开监管者任务：它说自己读不读得到别的任务 | | |
| K9 | 回调度者任务说“报告”：它有没有运行 `clock.py --card`、填草稿、用 `check_brief.py` 查过再发；阶段报告是不是 20 行以内、“要你做的”不超过 3 件、每件写了去哪个任务 | | |
| K10 | 从你发出第一段话，到第一个任务开出来，一共几分钟 | | 立项截止是第 10 分钟 |

哪一步它没照 SKILL.md 做，把它当时的原话记下来。这比“成 / 不成”有用：看得出是技能没写清楚，还是平台不允许。

## 平台行为：每个编号测什么

官方文档对下面这些行为没有写明。“现在的假设”是 SKILL.md 默认做法所依据的；假设不成立时的退路在 `references/manus-platform.md` 第一节。

| 编号 | 问题 | 现在的假设 |
|---|---|---|
| T1 | 技能里要求开独立任务、用户只回了一个“开”，算不算用户要求了 | 算 |
| T2 | 主任务会不会自己等子任务做完再汇总 | 不会。所以巡检靠用户说“报告”触发 |
| T3 | 主任务读子任务时，读不读得到工作区里的文件 | 不依赖它：回报和移交说明都要求放在最后一条消息里 |
| T4 | 子任务能不能读兄弟任务、能不能给主任务发消息 | 不能 |
| T5 | 子任务能不能再开子任务；主任务看不看得到孙任务 | 不能。分叉都由调度者开 |
| T6 | 用户手动开的任务，能不能读项目里的所有任务 | 不能 |
| T7 | 开任务或发消息时，能不能附任务引用；能不能指定模式和技能 | 能附任务引用 |
| T8 | 定时自动化能不能挂在已有的任务上续跑 | 能，但默认不用 |
| T9 | 网站代码库里的文档，另一个网站任务读不读得到最新的 | 读得到 |
| T10 | 派工单写了“不发布”，子任务守不守 | 守 |
| T11 | 游戏项目能不能几个任务同时改 | 不能 |
| T12 | 在 Studio 里让主任务开并行任务，开出来的是本地任务还是云端任务 | 按云端处理 |
| T13 | 任务停下或等确认时，用户在别处能收到什么提示 | 没有可靠的提示。所以阶段报告里列出每个等用户的任务 |
| T14 | 技能的脚本在任务的机器上能不能跑：有没有 `python3`，读不读得到技能目录里的 `templates/` | 能 |

每条提示词开头都要求“做不到就直说”，防止它绕路硬做，把结论弄混。

## 第一组：任务之间的通信

不需要网站。

### 准备

新建一个 Project，名字随意，比如“通信测试”。在里面新开一个任务，下面叫它**主任务**。

### 第 1 步：开任务（T7 的一部分）

在主任务里发：

```text
这是一次平台机制测试。请严格照做，做不到就直说，不要绕路。

在此项目中开两个独立任务，不要在这里代做：
- 任务 A：在工作目录新建 a.md，内容写“A 第 1 版”，然后停下。
- 任务 B：在工作目录新建 b.md，内容写“B 第 1 版”，然后停下。
每个任务给一份自含的说明。开好后，给我每个任务的链接。

然后如实回答：你开任务、读任务、给任务发消息，各用的是什么工具，各有哪些参数？
开任务时能不能指定模式（比如 Max）、指定要加载的技能、附上对其他任务的引用、指定要编辑的网站？
```

看什么：

- 有没有弹 **Allow these actions?**。
- 项目里是不是多了两个任务，各有链接。
- 它说的工具参数里，有没有模式、技能、任务引用、网站这几项。

### 第 2 步：等、读、发（T2、T3）

在主任务里发：

```text
1. 不用我再问：等 A、B 都停下后，告诉我它们各自的状态，以及 a.md、b.md 的内容。
2. 然后给任务 A 发一条消息：“把 a.md 的内容改成‘A 第 2 版’”。等它做完，再读一次 a.md，告诉我内容。
```

看什么：

- T2：它会不会自己等到两个任务都停下再回答，还是答一句“还在跑”就结束。
- T3：它报出来的是不是文件里的原文。
- 任务 A 有没有收到消息并照做。

### 第 3 步：子任务的权限和嵌套（T4、T5）

打开任务 A，在里面发：

```text
这是平台机制测试，做不到就直说，不要绕路。
1. 读同一个项目里任务 B 的最新进展，以及它的 b.md 的内容。
2. 给开出你的那个主任务发一条消息：“A 报到”。
3. 在此项目中再开一个独立任务 A1：新建 a1.md，内容写“A1 第 1 版”。给我链接。
```

看什么：

- T4：第 1、2 件事做不做得成。
- T5：第 3 件事做不做得成，有没有再弹 Allow。

### 第 4 步：主任务看不看得到孙任务（T5）

回主任务发：

```text
列出这个项目里现在所有的任务，包括不是你开的，以及它们各自的状态。读任务 A1 的 a1.md，告诉我内容。
```

### 第 5 步：独立的监管者（T6、T7）

在这个 Project 里**手动**新开一个任务，下面叫它任务 S。在里面发：

```text
这是平台机制测试，做不到就直说，不要绕路。
列出这个项目里所有的任务和它们的状态；读每个任务最新的一条消息，以及它们各自的 .md 文件内容；汇成一张表。
做不到的话，说明卡在哪一步、缺什么权限。
```

如果它做不到，回主任务发：

```text
给任务 S 发一条消息：“读任务 A 和任务 B 的最新进展，汇成一张表。”发的时候把任务 A、B 作为任务引用附上。做不到就直说。
```

再回任务 S 看它这次读不读得到。

看什么：

- T6：手动开的任务能不能直接读项目里的全部任务。
- T7：主任务能不能把任务引用传给另一个任务。

### 第 6 步：让任务定时醒来（T8、T13）

在任务 S 里发：

```text
建一个定时自动化：每 5 分钟运行一次，每次都在这个任务里继续，不要新开任务。
每次运行做的事：读任务 A 的 a.md；内容和上一次不一样，就告诉我新内容；一样就只回一个字“无”。
运行 3 次后停掉。做不到就直说。
```

它建好后会让你审核，启用它。然后去任务 A 发一句“把 a.md 的内容改成‘A 第 3 版’”，再离开任务 S，去别的页面等 5～10 分钟。

如果它建不了，去左侧栏的 Automations → Create → Schedule 手动建一个，看有没有“在同一个任务里运行”的选项、能不能选到任务 S。

看什么：

- T8：它是不是按时在任务 S 里自己醒来、报出了新内容。
- T13：它醒来和回话的时候，你在别的页面收到了什么提示：侧边栏有没有标记，浏览器、桌面或手机有没有通知。

测完把这个自动化删掉：Automations → Manage → More actions → Delete。

## 第二组：共享文档和发布

顺着任何一次网站练手做，不用单独花时间。

### 第 7 步：代码库里的文档别的任务读不读得到（T9）

在建这个网站的任务里发：

```text
在代码库根目录新建 coord/ARCHITECTURE.md，内容写一行“架构第 1 版”，存一个版本。不要发布。
```

在网站控制台点 **Edit in new task** 开第二个任务，发：

```text
这是平台机制测试。读代码库里的 coord/ARCHITECTURE.md，把内容原样告诉我。再新建 coord/tasks/B2.md，写一行“B2 报到”，存一个版本。不要发布。
```

回第一个任务发“把 coord/ARCHITECTURE.md 改成‘架构第 2 版’，存一个版本；再读 coord/tasks/B2.md 告诉我内容”。然后回第二个任务，**不要点 Sync**，发“再读一次 coord/ARCHITECTURE.md，告诉我内容”。

看什么：

- 两个任务读到的是不是对方刚写的最新内容。
- 不属于网站功能的文档文件，会不会被留在代码库里。

### 第 8 步：发布守不守得住（T10）

- 第 7 步里两次都写了“不要发布”。看这两个任务最后有没有自己发布。
- 在网站的项目设置里找 Agent Publish 这个开关，记下它在哪、默认是开还是关。

## 第三组：可选

- 第 9 步（T12）：在 Manus Studio 里打开 Work locally，选一个文件夹，让主任务开两个独立任务。看开出来的任务是本地的还是云端的，它们看不看得到同一个文件夹。
- 第 10 步（T11）：对一个 Game Dev 的游戏项目，试着开第二个任务去改它。

## 第四组：和效率有关的四个小测试

这四条决定技能怎么省时间。每条两三分钟，互不依赖，可以只做一部分。在一个随便建的测试 Project 里做（P4 会改掉这个 Project 的主指令），先把 demo-first 加进它的技能库。每条都是新开一个任务，把提示词原样贴进去。

**P1 新任务用什么档位。** 现在不知道主任务开出来的任务是继承它的档位，还是用默认档。

```text
这是一个平台行为测试，照字面做，不要多做。
1. 告诉我：你这个任务现在用的是哪个模式或档位。
2. 在本项目里开两个独立任务，第一条消息都写：“这是测试。只回复一句话：你现在用的是哪个模式或档位。然后结束。”第一个任务请指定用 Lite 档，第二个请指定用 Max 档。
3. 开完后告诉我：开任务时你能不能指定档位；能的话是怎么指定的，不能的话原因是什么。把两个任务的链接给我。
```

做完后点开这两个新任务，看各自的模式菜单里显示的是哪一档。

**P2 新任务能不能自己读到技能。** 能的话，派工单里就不用每次都带上整套规矩。

```text
这是一个平台行为测试，照字面做，不要多做。
在本项目里开一个独立任务，第一条消息原样写成下面三行，不要改写：
/demo-first 你是探索者
这是测试。只做两件事：说出你读到的探索者派工单模板的文件名，列出它所有的小节标题。
做完就结束，不要开工。
开完把任务链接给我。
```

做完后点开新任务，看它有没有列出小节标题（应该有：你要回答的问题、时间盒、范围、怎么做、记录、回报等）。

**P3 开任务时能不能带附件。** 能的话，派工单作为文件带过去，主任务不用把全文再打一遍。

```text
这是一个平台行为测试，照字面做，不要多做。
1. 在你的工作区里写一个文件 note.md，内容只有一行：暗号是蓝色大象。
2. 在本项目里开一个独立任务，把 note.md 作为附件带给它，第一条消息写：“这是测试。读附件，只回复里面的暗号，然后结束。”
3. 告诉我：你是怎么把文件带过去的；带不了的话，原因是什么。把任务链接给我。
```

**P4 项目主指令能不能由它来改，新任务读不读得到。**

```text
这是一个平台行为测试，照字面做，不要多做。
1. 把本项目的主指令更新成一句话：本项目的暗号是黄色长颈鹿。（会弹出批准卡片，我来点。）
2. 我批准之后，在本项目里开一个独立任务，第一条消息写：“这是测试。本项目的暗号是什么？只回复暗号，然后结束。”
3. 把任务链接给我。
```

| 编号 | 记什么 | 结果 |
|---|---|---|
| P1 | 主任务自己是哪一档；它说能不能指定档位；两个新任务的模式菜单里各显示哪一档 | |
| P2 | 新任务有没有加载技能；有没有列出小节标题 | |
| P3 | 它说附件是怎么带的；新任务答没答出“蓝色大象” | |
| P4 | 批准卡片出没出现；新任务答没答出“黄色长颈鹿” | |

结果怎么用：

- P3 能带附件：派工单改成作为附件发，第一条消息只写几行。
- P3 不能、P2 能：第一条消息改成 `/demo-first 你是<角色>`，加上要填的那几项。
- 都不能、P4 能：各角色的规矩写进项目主指令，派工单只带要填的那几项。
- 都不能：保持现在的做法，派工单整份发。
- P1：定各角色用哪一档，由谁来设。
