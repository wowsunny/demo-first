# 在 Manus 上实测

两件事要在真实账号上测：技能本身好不好用（第一组），和它依赖的平台行为是不是真的那样（第二、三组）。先做第二组：它只要十几分钟，结果决定第一组怎么跑。

- 需要：一个能同时跑多个任务的账号。Free 账号同时只能跑 1 个任务，只能测到“开不出并行任务”的退路。
- 花费：会用掉一些积分。每一步的活都故意做得很小。
- 结果记在每组后面的表里。哪一步它没照做，把它当时的原话记下来：这比“成 / 不成”有用，看得出是技能没写清楚，还是平台不允许。
- 每条提示词开头都要求“做不到就直说”，防止它绕路硬做，把结论弄混。

## 已经测过的

| 编号 | 问题 | 结果 |
|---|---|---|
| P1 | 主任务开出来的任务用哪一档 | 2026-11-20：能指定，指定了就照指定的来，不继承主任务的档位。主任务是 Max 的超高档；要 Lite 的那个是 Lite，要 Max 的那个是 Max 的高档。任务自己说不出自己是哪一档，要人去模式菜单里看。开出来的任务和主任务在列表里是并列的，没有层级 |
| P5 | 任务内部的子代理 | 2026-11-20：两个子代理同时跑完，结果以文字交回给开它的任务。档位在每个子代理上单独设（`effort_level`，可选 lite、standard、max），都不设就是 lite。开之前要申请调用次数，申请 2 次、上限给了 4 次。子代理不和用户对话。它照工具说明讲、没有实测的两点：子代理默认跑在开它的任务所在的环境里，要给它用的文件必须明确列出来；它写的文件不随结果带回 |

官方文档、接口文档和博客里都找不到这个工作流工具的说明。上面这些只来自一次实测和 Manus 自己的描述，换一个账号或换一种客户端不一定一样，所以第二组的 P6 要先测。

## 第二组：新结构依赖的四件事

在一个随便建的测试 Project 里做，先把 demo-first 加进它的技能库。每条都是新开一个任务，把提示词原样贴进去。

**P6 子代理做小样时，还能不能接着聊；它写的文件看不看得到。** 发出后不要等，马上再发一句：“子代理还在跑吗？现在北京时间几点？”

```text
这是一个平台行为测试，照字面做，不要多做。
1. 用你的工作流工具开一个子代理，档位用 max：在你的工作区写一个单文件网页 lab/quick/demo.html，页面上有一个按钮，点一下数字加一。写完交回文件路径和一句话说明。
2. 子代理运行期间不要干等。我会马上再发一条消息问你问题，请先回答我。
3. 子代理交回后告诉我：它交回的原文；你读不读得到 lab/quick/demo.html；然后把这个网页给我看，并说明你是用什么办法给我看的。
```

**P7 任务能不能指定名字、能不能附任务引用。**

```text
这是一个平台行为测试，照字面做，不要多做，做不到就直说。
1. 在本项目里开一个独立任务，标题指定为“测试项目 - 探索者 - 甲”。第一条消息写：“这是测试。在工作区新建 a.md，内容写‘暗号是绿色河马’。然后只回复一句‘甲完成’，结束。”
2. 等它结束后，再开一个独立任务，标题指定为“测试项目 - 建设者”，并把上一个任务作为任务引用附给它。第一条消息写：“这是测试。读被引用的那个任务：它最后一条消息是什么？它的 a.md 里的暗号是什么？读不到就直说卡在哪。然后结束。”
3. 告诉我：标题你是怎么指定的；任务引用是怎么附上的；做不到的话原因是什么。把两个任务的链接给我。
```

**P8 各任务是不是在同一个文件夹里工作。** 全景页和共用台账都靠它。在桌面应用里打开 Work locally、选一个空文件夹再测；在网页版里也测一次，对比结果。

```text
这是一个平台行为测试，照字面做，不要多做，做不到就直说。
1. 在当前工作目录新建 shared-test.md，内容写“主任务写的第 1 行”。告诉我这个文件的完整路径，以及你现在是在我的电脑上还是在云端的机器上工作。
2. 在本项目里开一个独立任务，第一条消息写：“这是测试。读 <上一步的完整路径>，把内容原样告诉我；再在同一个文件末尾加一行‘子任务写的第 2 行’。读不到就直说，并告诉我你的工作目录是什么。然后结束。”（把尖括号换成真实路径。）
3. 等它结束后，你再读一次 shared-test.md，把内容原样告诉我。
```

**P9 它有哪些工具。** 工作流工具就是这样问出来的；别的没写进文档的能力，也可能问得出来。

```text
这是一个平台情况调查，照字面做，不要多做，不要实际调用工具。
请列出你现在可以使用的全部工具，按用途分组。每个工具写：名字；一句话说明它做什么；它的使用说明里和下面这些事有关的要点：并行、后台运行、子代理或工作流、开独立任务或给任务发消息、任务引用、定时或自动化、文件在任务之间或子代理之间怎么传、技能、项目指令和项目文件、通知用户、等用户确认。
最后单独列一节：使用说明里明确写了“应该用”“不该用”“上限”“默认值”的地方，逐条列出。
你看不到或不确定的，直接说看不到，不要猜。
```

| 编号 | 记什么 | 结果 |
|---|---|---|
| P6 | 它是不是在子代理交回之前就回答了你；子代理写的文件它读不读得到；你最后看没看到那个网页，它是怎么给你看的 | |
| P7 | 侧栏里两个任务的名字对不对；第二个任务答没答出“绿色河马”；它说标题和引用各是怎么指定的 | |
| P8 | 桌面应用和网页版各一行：子任务读没读到第 1 行；主任务最后读没读到第 2 行；两边的工作目录各是什么 | |
| P9 | 把它的回答整段存下来 | |

结果怎么用：

- P6 不能边跑边聊：深聊里的小样改成“先聊完这一轮，再开子代理等它交回”。子代理的文件读不到：改成把内容放进交回的文字里。开不了子代理：各会话按先后自己做，见 `references/manus-platform.md` 第一节。
- P7 指定不了标题：派工单的第一行已经是会话名，请用户手动改名。附不了任务引用：调度者留下当转交的人，建设者落地时请用户贴移交说明。
- P8 共用文件夹：派工单只发路径，全景页可用，建设者和监管者直接读文件（`references/manus-platform.md` 第三节）。不共用：派工单整份发，全景页只有调度者自己的那一份，各会话的进展靠监管者巡检来看。
- P9：有没写进文档、但用得上的工具，就改 `references/manus-platform.md`。

## 第一组：试用技能本身

### 准备

1. 在仓库根目录运行 `python dev/pack.py`，得到 `dist/demo-first.zip`；或者直接用仓库链接。
2. Manus → Skills → **+ Add** → **Upload a skill** 上传 zip，或者 **Import from GitHub** 贴仓库链接。
3. 新建一个 Project，把 demo-first 加进它的技能库。
4. P8 测出来各任务能共用文件夹的话，在桌面应用里打开 Work locally、选一个空文件夹来做这一组。Windows 上先在权限模式那里点一次 Enable safe modes。
5. 在 Project 里新开一个任务，模式选 Max 的极致档（嫌每一轮太慢就用超高档），发下面这段话。

```text
/demo-first
我想做：一个网页版的番茄钟。25 分钟倒计时，结束时有提示音，并显示一句鼓励的话。
交什么：线上链接
没把握的地方：结束时的提示音用哪一种好听又不吓人；鼓励的话是写死一组，还是让模型现写；计时的圆环长什么样
```

### 边看边记

它会先和你聊几轮，再发分工确认；你回“开”，它开出会话，告诉你先去哪。它不会问你期限，也不该催你。想省积分，开出会话后可以把不看的停掉。

| 编号 | 看什么 | 结果 | 备注 |
|---|---|---|---|
| K1 | 它有没有运行 `init_ledger.py`（带 `--name`）；脚本跑没跑通；输出的中文是不是乱码；它用的是 `python3` 还是 `python` | | 技能目录的路径是： |
| K2 | 深聊：每轮是不是最多 3 个问题、每个带推荐；每一轮要等多久 | | 用的是哪一档： |

| K15 | 说“先到这里”“冻结”“交付”“总检查”：对应的会话做得对不对；回调度者那里说一句，它有没有转给各会话 | | |

## 第三组：别的平台行为

官方文档对下面这些行为没有写明。“现在的假设”是 SKILL.md 默认做法所依据的；假设不成立时的退路在 `references/manus-platform.md` 第一节。有空再测。

| 编号 | 问题 | 现在的假设 |
|---|---|---|
| T1 | 技能里要求开独立任务、用户只回了一个“开”，算不算用户要求了 | 算 |
| T2 | 主任务会不会自己等子任务做完再汇总 | 不会。调度者派完工就退出 |
| T3 | 主任务读子任务时，读不读得到工作区里的文件 | 不依赖它：回报和移交说明都要求放在最后一条消息里 |
| T4 | 子任务能不能读兄弟任务 | 不能，除非开它的时候把兄弟任务作为任务引用附上（P7） |
| T5 | 子任务能不能再开独立任务 | 不依赖它：要加开会话，都回调度者那里 |
| T6 | 用户手动开的任务，能不能读项目里的所有任务 | 不能 |
| T8 | 定时自动化能不能挂在已有的任务上续跑 | 能，但默认不用 |
| T10 | 派工单写了“不发布”，探索者守不守 | 守 |
| T13 | 任务停下或等确认时，用户在别处能收到什么提示 | 没有可靠的提示。共用文件夹时看全景页，否则去监管者那里巡检 |
| T14 | 技能的脚本在任务的机器上能不能跑：有没有 `python3`，读不读得到技能目录里的 `templates/` | 能 |
| P2 | 开任务时第一条消息写 `/demo-first 你是探索者`，新任务会不会自己加载技能 | 不依赖它：派工单整份发 |
| P3 | 开任务时能不能带附件 | 不依赖它 |
| P4 | 项目主指令能不能由任务来改，新任务读不读得到 | 不依赖它：主指令只是多一层保险 |

T1 和 T14 在第一组里就能看出来（K6、K1）。P2、P3、P4 的提示词：

```text
这是一个平台行为测试，照字面做，不要多做。
在本项目里开一个独立任务，第一条消息原样写成下面三行，不要改写：
/demo-first 你是探索者
这是测试。只做两件事：说出你读到的探索者派工单模板的文件名，列出它所有的小节标题。
做完就结束，不要开工。
开完把任务链接给我。
```

```text
这是一个平台行为测试，照字面做，不要多做。
1. 在你的工作区里写一个文件 note.md，内容只有一行：暗号是蓝色大象。
2. 在本项目里开一个独立任务，把 note.md 作为附件带给它，第一条消息写：“这是测试。读附件，只回复里面的暗号，然后结束。”
3. 告诉我：你是怎么把文件带过去的；带不了的话，原因是什么。把任务链接给我。
```

```text
这是一个平台行为测试，照字面做，不要多做。
1. 把本项目的主指令更新成一句话：本项目的暗号是黄色长颈鹿。（会弹出批准卡片，我来点。）
2. 我批准之后，在本项目里开一个独立任务，第一条消息写：“这是测试。本项目的暗号是什么？只回复暗号，然后结束。”
3. 把任务链接给我。
```

这三条里有一条成了，派工单就可以不整份发（作为附件带过去，或者只发要填的那几项），调度者派工能快不少。
